# 启动画面 Splash

[文档首页](/) / [应用开发](/guide/project.md)

Splash 是系统在应用启动期间显示的画面。应用提供图标，系统负责背景、状态栏、加载指示和结束显示。JavaScript 与 Native 应用使用同一套清单配置。

[[toc]]

## 在应用清单中声明

在 `manifest.json` 的 `icons` 中添加可选的 `splash` 路径：

```json
{
  "icons": {
    "application": "assets/application.dti",
    "tile": "assets/tile.dti",
    "splash": "assets/splash.dti"
  }
}
```

这是清单片段，合并到项目原有的清单中即可。路径相对于应用包根目录；素材需要随包一起打包。声明的文件缺失时，打包检查会报错。

## 准备图标

使用正方形 DTI 图标，推荐按实际显示区域制作成 **96 × 96 px**。使用透明度遮罩格式时，系统以当前主色绘制；彩色格式保留图像颜色。图标中保留合适的透明留白，系统负责画面背景。

在 800 × 480 屏幕上，图标区域为 `x=352, y=176, w=96, h=96`，加载指示位于下方。Splash 素材是图标资源，整幅启动屏由系统合成。

图标加载失败时，系统依次尝试应用图标与默认应用图标。省略 `icons.splash` 则跳过这套应用启动画面。

## 何时显示与结束

系统按应用标识和版本记录启动耗时。首次启动或缺少对应记录时显示 Splash；已有记录且上次启动耗时低于 200 ms 时，后续启动可以跳过。需要强制展示的系统启动路径仍会显示。

这份耗时记录位于内存中，容量为八个应用记录，重启后重新收集。应用应以实际启动完成为目标，让系统决定画面的持续时间。

启动画面的显示、加载指示与收尾由宿主管理，应用通常无需调用显示或隐藏 Splash 的接口。应用进入后的网络请求、列表加载等异步工作，应在应用页面中呈现自己的加载状态，并及时响应输入。

## 开发与检查

1. 将图标放入项目资源目录，并声明 `icons.splash`。
2. 使用 `desktile build .` 构建安装包。
3. 安装后从设备桌面打开应用，检查图标、主题背景与首屏交接。
4. 连续退出重开，检查快速启动时跳过 Splash 的行为。

本地交互预览运行应用页面。设备桌面启动策略、启动耗时和系统 Splash 的交接效果需要在设备上验收。
