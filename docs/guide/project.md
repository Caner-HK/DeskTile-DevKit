# 项目结构

[文档首页](/)

一个 DeskTile 应用由清单、代码和资源组成。安装包是 `.dtapp` 容器，系统通过清单识别应用身份和入口。

| 路径 | 用途 |
| --- | --- |
| `manifest.json` | 应用身份、入口、权限与资源声明 |
| `src/` | 页面入口和应用逻辑 |
| `ui/` | 随项目复制的 JavaScript 组件与导航模块 |
| `locales/` | 语言目录和各语言消息 |
| `assets/` | 应用图标与图片 |
| `.desktile/types/` | JavaScript 编辑器使用的类型声明 |
| `dist/` | 构建生成的安装包 |

## 应用清单

`manifest.json` 定义包名、显示名称、版本、运行时、入口、SDK 要求、图标和权限。包名是稳定身份，应用更新应保持包名一致。显示名称可以为不同语言提供不同文字。

`version` 是可读版本，`version_code` 用于比较更新顺序。SDK 的 `minimum` 和 `target` 当前均使用 `1.0`；具体新增功能通过能力检测确认。

## 页面与逻辑

JavaScript 应用的文档入口建立组件树，脚本处理事件与业务状态。一个入口可以通过模块、导航及共享组件管理多个视图。公共框架负责组织常用导航行为，应用负责自己业务数据的含义。

## 资源

`assets` 存放图标和图片，`locales` 存放语言内容。安装包资源作为应用的只读输入；用户设置和业务数据应通过 SDK 存储接口写入应用私有空间。

## 开发配置

`desktile.json` 记录 SDK 版本和构建目标；`jsconfig.json` 配置编辑器检查。`.desktile/types` 为编辑器提供 SDK 类型，`dist` 保存构建结果。

构建器先在临时目录准备应用内容，再产生安装包。构建失败保留原有成功产物，成功后才替换输出文件。
