## 本地检查

`desktile build` 会检查包清单、入口和资源。`desktile check` 验证文件表、边界和各文件摘要。签名包的信任关系由设备安装流程判断。

`desktile preview` 在 Windows x64 本地窗口运行 JavaScript 或从源码构建的 Native 应用，使用实际 QuickJS、NativeAppRunner 和组件引擎。可以点击、拖动、滚动、输入文字、打开应用菜单，以及观察计时和数据保存。工具栏提供深浅主题、布局边界和电脑上的性能读数。预览保留实际 JavaScript 内存和单次执行预算，绘制帧率可以限制为 15、30 或 60 FPS。

本地可以检查 HTTP/HTTPS 请求、通知队列和点击回调、文件目录操作及共享日历与待办数据；具体范围见[预览服务说明](../tools/index.md#本地交互预览)。蓝牙、远程日历订阅、系统后台任务及硬件性能通过设备验证。Native 设备二进制也在设备上运行。鼠标验证之后，还应在屏幕上检查真实触摸手感。

`desktile screenshot` 使用同一组件渲染器输出所选 HTML 的 800×480 浅色与深色 PNG。

```sh
desktile preview my-app --locale zh-HK --theme light
desktile screenshot my-app --page src/index.html
```

## 生命周期场景

覆盖首次打开、返回前一页、退出、重新打开、权限拒绝、权限撤销、网络中断和存储写入失败。后台任务应验证应用退出后继续执行、重新进入后读取状态以及通知点击回到正确位置。

## 性能场景

用真实数据量进行连续滚动，包含长文字、跨天记录和图片。记录空闲、进入应用、操作之后、退出之后的内存，并重复操作确认资源能够释放。主机预览的耗时与内存用于主机工具诊断；设备性能以实机测量为准。

## 日志

设备开发者选项分别控制 USB 调试输入与输出。调试输入允许诊断指令，输出允许日常调试日志。异常和开机失败输出遵循系统自己的策略。用 DevKit 串口监视器保存当前会话日志，复现问题时保留 panic 和 backtrace 原文。
